## 1. Livros e Publicações Técnicas

### 1.1 Arquitetura de Software

**MARTIN, Robert C.** *Clean Architecture: A Craftsman's Guide to Software Structure and Design.* Prentice Hall, 2017.  
- Fundamenta a separação em camadas (Domain, Application, Infrastructure) adotada no projeto.  
- Disponível em: https://blog.cleancoder.com/uncle-bob/2012/08/13/the-clean-architecture.html

**EVANS, Eric.** *Domain-Driven Design: Tackling Complexity in the Heart of Software.* Addison-Wesley, 2003.  
- Base conceitual para Entidades, Value Objects, Repositórios e Linguagem Ubíqua.  
- Disponível em: https://www.domainlanguage.com/ddd/

**COCKBURN, Alistair.** *Hexagonal Architecture (Ports and Adapters).* 2005.  
- Padrão de Ports & Adapters utilizado para desacoplamento da infraestrutura.  
- Disponível em: https://alistair.cockburn.us/hexagonal-architecture/

**MARTIN, Robert C.** *Clean Code: A Handbook of Agile Software Craftsmanship.* Prentice Hall, 2008.  
- Princípios de código limpo, nomes significativos, funções pequenas e comentários relevantes.

### 1.2 Padrões de Projeto

**GAMMA, Erich; HELM, Richard; JOHNSON, Ralph; VLISSIDES, John.** *Design Patterns: Elements of Reusable Object-Oriented Software.* Addison-Wesley, 1994.  
- Padrões utilizados: Repository, Factory, Adapter.

## 6. Princípios e Metodologias

**SOLID Principles** — Robert C. Martin  
- Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion.  
- Disponível em: https://en.wikipedia.org/wiki/SOLID

**MoSCoW Prioritization Method**  
- Técnica de priorização de requisitos utilizada no planejamento do produto.  
- Must Have, Should Have, Could Have, Won't Have.  
- Disponível em: https://en.wikipedia.org/wiki/MoSCoW_method

**Conventional Commits**  
- Especificação para mensagens de commit padronizadas (`feat`, `fix`, `docs`, `test`, `refactor`).  
- Disponível em: https://www.conventionalcommits.org/
